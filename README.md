# FOF Exam Seating & Attendance Manager v1.6.2

澳門城市大學金融學院的離線考試座位及簽到表桌面工具。標準 64 位元 CPython 3.12–3.14、PySide6 Qt Widgets、SQLite、openpyxl；獨立專案，不修改或共用現有學生證明系統。運行時不需要網絡、帳號、CDN、API、遠端字型或雲端資料庫。

## 從 GitHub 下載

v1.6.2 亦提供固定檔名的[完整原始碼 ZIP](downloads/FOF_Exam_Manager_v1.6.2.zip)，校驗值及下載方法見 [downloads/README.md](downloads/README.md)。若舊 archive 連結為 404，先登入有此儲存庫存取權的 GitHub 帳戶，開啟 ZIP 檔案頁後使用 Download raw／下載原始檔。上載 ZIP 不會更改儲存庫的存取權。

在本 repository 頁面點 **Code → Download ZIP**，解壓後依以下步驟安裝 Python 原始碼版。

需要 Windows 獨立程式時，到 **Actions → Windows desktop build → Run workflow**，選 `main` 執行。成功後開啟該次執行，在 **Artifacts** 下載 `FOFExamManager-Windows`，解壓完整資料夾，再雙擊 `FOFExamManager.exe`。如果組織停用了 Actions，須由管理員啟用，或在 Windows 執行 [BUILD.md](BUILD.md) 的本地建置步驟。CI 產物仍需 Windows 桌面及 Excel 列印實機驗收。

## 安裝與啟動

Windows 10/11 可直接用批次檔，無須自行輸入指令：

1. 按 GitHub **Code → Download ZIP**，將整個 ZIP 解壓縮，不要在 ZIP 內直接執行。
2. 安裝 **標準 64 位元 Python 3.12（建議）、3.13 或 3.14**，安裝時勾選 **Add Python to PATH**。
3. 第一次雙擊根目錄的 **`首次安裝.bat`**。它會在 `%LOCALAPPDATA%\FOFExamManager\venv` 建立獨立 Python 環境、安裝 PySide6／openpyxl／Pillow，並實際檢查 Qt、圖像嵌入及官方模板；看到 **Setup completed** 後可關閉視窗。套件不放在 GitHub 解壓後的長路徑內，避免 Windows 路徑長度限制。
4. 以後雙擊根目錄的 **`啟動程式.bat`** 即可開啟系統。每次啟動會核對目前版本所需套件及圖像支援，缺少或不相容時自動執行安裝修復，不再僅依賴舊版安裝完成標記；修復時需要網絡，正常使用可離線。

若遇到 `Pillow 12.0.0 does not support Python 3.15` 或要求 C++ Build Tools，請安裝 [Python 3.12.10 Windows x64](https://www.python.org/ftp/python/3.12.10/python-3.12.10-amd64.exe)，再執行新版「首次安裝.bat」。可保留 Python 3.15；安裝器會優先尋找 3.12，亦支援一般版 3.13／3.14，不支援預覽版或 free-threaded 版本。舊版不相容虛擬環境會保留為 `venv.previous-<唯一碼>`，再建立相容環境；建立失敗會復原舊環境，不移動資料庫。未找到相容 Python 時會停止，不修改原環境。Windows 套件只使用預先編譯的 wheel，不會要求使用者編譯 Pillow。

首次安裝套件需要網絡，日常匯入、座位編排及 Excel 輸出均可離線。批次檔會檢查 Python 版本及 64 位元環境，出錯時保留訊息供排查。資料預設仍存在 `%LOCALAPPDATA%\FOFExamManager`，不會因重新解壓程式或重新安裝套件而刪除。根目錄另附可用記事本開啟的 `使用說明.txt`。

若舊版安裝在 PySide6 的 `objects-Debug`／`.qt\rcc` 路徑報 `OSError: [Errno 2] No such file or directory`，常見原因是解壓資料夾名稱加上 Qt 內部路徑超出 Windows 傳統路徑限制。下載 v1.2.1 或更新版本後重新執行「首次安裝.bat」，改用上述短路徑，會忽略程式目錄內未完成的 `.venv`，不必搬移或刪除學生資料。不需修改登錄檔或管理員權限；未完成安裝可再次執行，直到 Qt／模板檢查成功才允許由批次啟動。需要自訂環境位置的開發者可設定 `FOF_VENV_DIR` 為短且可寫入的本機路徑，安裝及啟動須使用相同設定。

需要手動安裝時，可在此專案目錄開啟 PowerShell：

```powershell
$fofVenv = Join-Path $env:LOCALAPPDATA 'FOFExamManager\venv'
py -3.12 scripts/prepare_environment.py "$fofVenv"
& "$fofVenv\Scripts\python.exe" -m pip install --only-binary=:all: -r requirements.txt
& "$fofVenv\Scripts\python.exe" run.py
```

`scripts/run_windows.cmd` 保留為啟動批次檔的內部入口。可在有網絡的相同 OS、架構與 Python 版本上預先執行 `pip download -r requirements.txt -d wheels`，將專案與 wheels 交給離線電腦，再用 `pip install --no-index --find-links wheels -r requirements.txt` 安裝。

Linux/macOS 原始碼開發使用 `python3 -m venv .venv`、`.venv/bin/python -m pip install --only-binary=:all: -r requirements.txt`、`.venv/bin/python run.py`。Windows 獨立程式建置見 [BUILD.md](BUILD.md)。發布時交付整個 `dist/FOFExamManager` 目錄，使用者不需要安裝 Python。

開發環境驗證：Linux、Python 3.12.14、Qt 6.12；自動化結果見 [TESTING.md](TESTING.md)。Windows 原生打包與實機 Excel 列印尚待 Windows 主機驗證，不能將 Linux 打包成果當作 Windows `.exe`。

## 功能與操作流程

1. **學生名單**：單檔、多檔或拖放 `.xlsx`。按完整科目代碼識別學年、學期、課程與授課班；每份檔案只讀完整匯總名單，忽略其他分班 Sheet。上方每份檔案只列一行，來源統一顯示「匯總」。學生的行政班不讀取、不填入、不顯示，不影響任何學生是否匯入。預覽核對後才寫入 SQLite。
2. **科目管理**：選「貼上表格・智能分析」，課程預設 BAECF 本科學士。從 Excel／Word 複製整張表，Ctrl+V 或按剪貼簿按鈕即可分析；辨識科目編號、雙語科名、多位教師，預覽可編輯。多編號同列（例如 BAE406 & BAE411）分成兩筆，必須人工核對才儲存。可保留單科新增／編輯，但不需要再製作科目 Excel 匯入檔。
3. **考場管理**：只填考場名稱、最多人數、備註及是否啟用。支援「貼上表格・智能分析」：直接貼上 Excel／Word 表格、Markdown、Tab、逗號或空格分隔的兩欄資料。相同名稱及容量自動去重；同一考場不同容量提示人工核對。可編輯或刪除預覽列，再一次儲存；已有考場更新容量並保留啟用狀態及備註，不能縮小至不足以容納現有編排。80 人自動對應 001–080，無須再輸入座號規則。指定／鎖定個別學生座位仍在座位頁處理。
4. **學年與考試**：依次選學年、學期、期中／期末；名稱自動生成，例如「2026–2027學年第一學期期中考試」。學院固定金融學院，課程固定 BAECF 的雙語本科名稱。這組設定就是原來的「批次」，用來共用同一學年學期的考試資料，無須另外取名。其下建立各科目日期、時段、教師、Intake、授課班與考場；使用考場清單預設全部不勾選，按需要自行選取；只顯示對應學年學期的授課班。同一科目可有多個場次。按「修改場次／考場」可保留原場次加／減／更換考場：現有考場逐行選擇新考場或移除，另勾選新增考場。更換保留學生、次序、座號及鎖定；容量不足、已編排座號不適用、時段或合場座號衝突時整次修改回滾。移除先備份，該考場學生（包括鎖定者）回待分配，並清除本場次復原歷史；其他考場編排及已有 Excel 檔案保留。修改後須重新生成文件。
5. **考場編排**：把班級卡片拖到考場卡片，或選取班級與考場後雙擊班級。考場卡片會按實際班級行高展開，完整顯示已分配班級；內層沒有捲軸，滾輪統一捲動外層考場列表。可按「加／減／更換考場」修改目前場次。可將班級拖回左側移出，或選考場再按「移出選中考場班級」。移出直接執行，不再彈確認視窗，可按「復原」還原；僅該考場的該班學生回到待分配，其他考場的座位及排序保留；有鎖定座位須先解除。人數、容量使用率與待分配清單即時更新。容量不足可選「拆分班級」或取消；拆分對話框可自訂人數及逐一勾選學生。剩餘學生保持待分配。可新增考場、調整參加班級、復原、重做及驗證完成。
6. **座位調整**：上下拖放學生、移至首位、指定名單序號、Ctrl 選兩人交換。預設座號跟隨次序重編。指定座號可鎖定，鎖定者的實際座號保持不變；其餘学生跳過該號。特殊安排及備註僅內部顯示。解除鎖定後可移回待分配或調至其他考場；移回待分配直接執行，可復原／重做。搜尋期間停用拖放；清除搜尋可再排序。「隨機打散座位」會先確認人數，只將目前考場未鎖定的學生隨機分配至現有已佔用座號；鎖定者的座號及名單位置、空座及其他考場均保留。特殊安排與備註跟隨學生，可復原／重做，重新開啟程式仍保留結果；打散後須重新生成 Excel。
7. **文件生成中心**：按批次、科目、日期、考場篩選；預設按批次／科目分組，可改按最後修改／最後生成由新到舊排列，同一場次的考場保持相鄰。勾選項目或全選；生成前要求所有場次學生已分配、無衝突、表頭完整。選擇輸出資料夾，逐份產生文件并顯示結果。已有同名檔案逐份提示覆蓋／另存／跳過。可打開文件及輸出資料夾。「刪除勾選考場項目」先備份，再刪除選中考場配置及座位，學生回待分配；其他考場、學生修讀及已有 Excel 檔案保留，相關場次復原歷史清除。
8. **Dashboard**：學生、科目、批次、場次、分配和完成數直接從 SQLite 計算。雙擊場次繼續編排。
9. **試卷文件及印刷**：選擇右上方場次，自動帶入科目、教師、學年學期、日期時間、授課班及考場。每科設定中文／英文內容頁數、公式表處理、審批方式、開／閉卷及送審人；設定自動保存。可分別生成附件一、二、三及印刷統計。附件一、三不依賴審批封面或試卷頁數。「打開輸出資料夾」首次生成前亦可使用，預設開啟本機資料目錄下的「輸出文件」；選擇其他輸出位置後，會打開已選位置或最近生成的文件子資料夾。每個輸出批次使用新資料夾，保留之前手動修改的文件。「印刷總表（多科）」可勾選同批次場次，合計後才換算整令／整箱。
10. **設定與資料備份**：查看資料庫路徑、匯入與生成記錄，執行備份和還原。

所有編排操作自動保存，復原／重做歷史也保存於資料庫。「保存草稿」確認目前已保存狀態。關閉程式後可繼續。

學生名單及座位調整頁均可按「特殊學生標記」，填寫原因（例如作弊）並保存；以學生身份跨科目、學年保存，重新匯入或改學號／姓名不會清除。學生清單可篩選特殊學生，考場卡片及生成清單顯示特殊學生人數，座位調整顯示內部原因。可在「特殊學生名單」搜尋、編輯或解除；刪除某科修讀甚至最後一份名單時，已標記學生的身份及標記仍保留，日後重新匯入同一學號會繼續提醒。

每次生成含特殊學生的考場時，會列出科目、考場、學生、目前座號及原因。可選「前往所選考場調整座位」，直接跳到該考場並定位該學生，再用「座號／鎖定／特殊安排」指定及鎖定位置；或確認安排後繼續生成。再次生成仍會提醒，不會永久略過。標記不自動改座、不當作考試衝突，原因只留在本地系統，不寫入 Excel、班級座號索引或一般生成記錄。


## 真實附件分析

以 `261BAECF3DBAE30500` 為例：`26` = 2026–2027 學年、`1` = 第一學期、`BAECF` = 應用經濟學學士位課程（中文學制）、`3D` = 三年級 D 授課班、`BAE305` = 公司金融科目編號。保留原始完整代碼、年級及學年學期；不讀取學生行政班。亦支援 `261BAECF1BBAE10300CB`：識別為 1B 授課班、BAE103、2026–2027 第一學期，保留完整尾碼 CB。

| 檔案 | 授課班 | 完整科目名單 |
|---|---|---:|
| 3D.xlsx | 3D | 30 |
| 3E.xlsx | 3E | 28 |
| 3F.xlsx | 3F | 34 |
| 3G.xlsx | 3G | 35 |

真實名單共 **127 人**、127 個不同學號。3D+3F → G2209 **64 人**；3E+3G → G2207 **63 人**。舊版 122 人是把行政班誤當授課班的錯誤結果，已修正；不再按行政班或檔名篩除修讀學生。

原 G2209 Seat Plan 第 80、81 列重複引用 Attendance 第 81 列，會漏掉一名並重複另一名。本工具以資料模型直接渲染，沒有此公式問題。詳見 [ANALYSIS.md](ANALYSIS.md) 與 `resources/excel-analysis.json`。

## Excel 匯入要求

只接受 `.xlsx`。辨識「帳號／學號／Student ID」「姓名／中文姓名」「英文姓名」，支援原附件位於第 8 或第 9 行的表頭。科目資料優先來自表頭前的完整「科目代碼」，並以「教務科目代碼」核對短科目編號。沒有完整代碼的單 Sheet 通用名單，可用明確的「授課班」欄或「1H.xlsx」這類完整年級班別檔名指定授課班；普通「班級／Class」欄不會讀取。無法可靠識別時顯示提示，不執行其中的公式。

姓名支援分欄、中英同格、多行，中文與拼音緊接亦可拆分。「姓名」欄已有正式拼音／英文全名時優先採用，不以旁邊「英文姓名」欄的暱稱取代。只有英文／拼音的學生可正常匯入，中文欄留空；中文名前的國籍括號保留。含空格、連字號、撇號的英文保留；曖昧格式保留原文並要求人工核對。學號保留文字，數值搭配全零格式會保留前導零；超過 Excel 精度或非整數學號要求人工確認。兩欄原始姓名均保存於資料庫。

每份多 Sheet 檔案只讀一份匯總（支援「匯總／汇总／Summary／總表／总表」），其他 Sheet 不參與匯入。找不到匯總時提示提供完整匯總，不會合併分班頁。單 Sheet 名單作為一份完整名單，預覽來源同樣統一顯示「匯總」。同科目同學期同學生重複仍須人工核對；不同學年的修讀分開保存。學生身份依學號識別但使用 UUID 關聯，同姓名不同學號不合併，同學號可修讀不同科目。

重新匯入顯示新增／移除／姓名更改／無變化。預設保留舊修讀關係；勾選「差異合併」才停用已移除記錄。已有座位不會刪除，會阻止生成直到使用者在座位頁移除該記錄。未變動者的座位與排序保持。手動「停用修讀記錄」只影響此科此班，其他科目不受影響。

學生清單可按科目、授課班、學年、學期及匯入來源組合篩選，再搜尋學號或姓名；上方只顯示目前篩選的筆數、學生數及班數，不再逐班列出長文字。預期人數功能已移除，舊版已填的預期人數亦不再阻止生成。Ctrl／Shift 多選後可「刪除選中修讀記錄」；選定授課班後可「刪除所選班級名單」，刪除該班全部修讀記錄（包括停用記錄，不受姓名搜尋限制）。刪除前先備份及確認數量，刪除對應座位，保留其他科目身份及編排；清空的班級移除，相關場次復原歷史清除。備份位於資料庫同目錄的 `before_roster_delete_*.sqlite3` 或 `before_allocation_delete_*.sqlite3`。

科目貼上支援「課程代碼｜科目編號｜中英文科名｜任課教師」，或把中英文科名分成兩欄。Excel 的帶引號多行儲存格、HTML 表格換行和多編號列均可分析；不清楚的內容保留在預覽並要求人工確認。公式不執行、不匯入為學號；巨集檔拒絕，外部連結不載入執行。

## Excel 輸出規則

採用已去除學生資料的官方雙工作表模板。Attendance 名字分 D 中文、E 英文；Seat Plan 分 D:E 中文、F:G 英文，沿用原合併布局。中英文大学與課程、學年學期、考試類型、科目、Intake、教師、日期、時間、考場和考生數均同步更新。

每人一列，動態生成，不留固定 80 行或舊座號。兩張表的中文及英文姓名均水平、垂直置中。中文姓名「標楷體」12 pt，英文、學號、數字 Times New Roman 12 pt；目標電腦須有相應字型，否則 Excel 會替代顯示。保留官方表頭合併、欄寬、邊框、A4 直向和頁邊距（左右 1.8 cm、上下 1.9 cm）；依長姓名調整行高、更新打印區域。大學、課程、考試資料及欄名只在第一頁出現；不設定列印重複標題，第二頁起直接接續學生名單。固定一頁寬、高度不限，不插入手動分頁線，由 Excel 按實際紙張可印高度自然分頁，避免固定每約 15 人截頁留下大幅空白。Attendance 保留出缺席及監考簽名區；Seat Plan 不含簽到、簽走或簽到說明。

兩張表直接写值，不依賴 Excel 重新計算，離線或 `data_only` 開啟均有完整學生資料。內部特殊安排與備註永不輸出。開啟時由 A1 顯示完整大學及課程表頭，不凍結窗格、不啟用工作表保護，可直接編輯。教師列沿用官方模板 16.5 pt 行高、靠右對齊；較長教師名單縮小字型以配合欄寬。

簽到表最後一欄為「備注 / Remark」，供監考員填寫；系統內部學生備註不會自動帶入此欄。

混班時，可在文件生成中心勾選「簽到表末尾附班級座號索引（細字）」（預設不勾選）。末尾以 9 pt 灰色小字列出各授課班的實際座號，例如「3D：001–004、007、010–012」。只合併真正連續的座號，打散後零散座位仍準確列出，不會以最小至最大號誤包其他班學生。索引不加在個別學生旁，亦不加到座位表；仍保留不重複表頭及自然分頁。

開啟已有資料庫時，會自動拆分能可靠辨識的舊「中文＋拼音」姓名，並將錯放在中文欄的英文全名移到英文欄。修改前先建立同目錄 `before_name_split_<唯一碼>.sqlite3` 備份；保留原文、修讀關係、座號、鎖定及復原歷史，相關場次轉為草稿等待重新生成。已分欄的姓名保留使用者填寫的英文名，不確定的格式維持原文，可重新匯入或人工核對。修正人數及備份路徑顯示於視窗底部；視窗標題顯示 v1.6.2，方便確認正在使用新版。

亦支援 VBA 拆分後的「中文姓名／英文拼音」表頭；同時有「英文拼音」及「英文姓名」時，優先拼音並保留原文。重新生成 Excel 並選擇覆蓋或另存，舊輸出不會自動更新。4B／4C／4D／4E 原始名單已驗證為 30／28／32／26 人，共 116 人；附件及含學生資料的測試輸出不放入 repository。

檔名：`BAE305_公司金融_2026-10-14_1900_G2209.xlsx`。先写同目錄临時檔，重新讀取驗證兩張表的人數、學號、姓名及座號，成功才原子發布；驗證失敗不取代已有檔案。文字值以 Excel 字串保存，即使姓名以 `=` 開頭亦不成公式。

同場次學生只能有一座；同時段考場禁止重用，除非雙方場次皆明確啟用合場。合場共用容量及座號池，以所有重疊場次保守預留，不容許重複座號。同時段同學生的第二次分配會被拒絕。

## 試卷文件、印刷及官方版面

- **份數與卷別**：只按授課班判斷，A／1A 等 A 班使用英文卷，其他班為中文卷；每個有應考學生的授課班另加 1 份後備。班級拆到多考場不會重複加後備。內容頁數不含封面，內容雙面，封面另佔 1 張單面；每份用紙為 `ceil(內容頁數 / 2) + 1`。
- **公式表**：逐科、逐卷別選擇沒有／已包含在內容頁數／獨立印刷。已包含不重複計紙；獨立印刷必須自行填頁數、含後備的實際份數、單雙面及有無獨立封面，未填齊不估算總用紙。
- **A4包裝**：預設 500 張／令、5 令／箱，可修改。顯示精確張數及令／餘張，並向上取整整令／整箱。25 人英文 A 班、230 人中文 B–H 班，內容分別 13／10 頁，結果為 `(25+1)×8 + (230+7)×6 = 1630張`，即 3 令 130 張，約需 1 箱。
- **附件一**：同科同場次只輸出一份評審記錄，不分中英文卷；帶入課程資料，評審結論、簽署及後續評審日期留白。
- **附件二**：先明確選擇需要／不需審批。需要審批時，匯入中文／英文已審批 PDF，原始位元組及 QR 保留，輸出時以 SHA-256 校驗，不修改或自行製造審批碼。PDF 存在本機 SQLite 備份內，不依賴原檔路徑。新場次不自動沿用舊場次的審批文件。不需審批才由系統填寫官方空白封面，頁數顯示內容頁數加 1 頁封面。
- **附件三**：每個有學生的考場一個 Excel 表格頁；袋不夠用時可重複列印同一頁多份。印刷／使用／未用、實考／缺考、現場情況及監考簽署由使用者按實際情況填寫，不會帶入學生內部標記原因。尚未完成考場分配時不輸出試卷袋。
- **Excel編輯與版面**：校徽、線條、原有文字及填塗格使用使用者提供的官方空白 PDF 底稿；填入內容以可編輯文字框定位，連結至「資料」頁 B 欄。在 Excel 修改 B 欄可更新表格，亦可直接修改文字框。不要以 openpyxl 等第三方工具重新儲存此類文件，否則可能移除文字框。只列印官方表格頁，不列印「資料」頁。表格設為 A4 直向一頁，模板自身保留原有邊界；Microsoft Excel 的文字連結及實際印表機對齊仍須 Windows 實機試印確認。
- **統計表**：數量為生成時快照；修改頁數／份數請回程式重算。多科總表會對整批張數一次換算令／箱，不逐科取整。實際試卷及已審批文件只保存在使用者本機，不放入 GitHub。

## 從 v1.0 升級

下載新版或重新執行 Windows Actions 打包。使用同一資料目錄啟動，v1／v2／v3 舊版資料庫會先自動備份為 `before_upgrade_v4_<唯一碼>.sqlite3`，再升級至 schema v4，加入學生標記及考務文件資料表，原有名單及鎖定座位保留。標記包含於新版資料備份；還原舊版備份時會先在隔離副本升級，內容以該備份為準（較舊備份可能尚未有標記）。重新匯入 3D/3E/3F/3G 名單以修正授課班；原有學生、修讀關係 ID、座號、鎖定和備註保留，新增的修讀學生留在待分配。舊版備份亦可還原，先在隔離暫存資料庫升級，不修改備份原檔。

## 本地資料、備份與還原

Windows 預設 `%LOCALAPPDATA%\FOFExamManager\fof_exam.sqlite3`；Linux 預設 `~/.local/share/FOFExamManager/fof_exam.sqlite3`。可用 `python run.py --data-dir <資料目錄>` 指定另一目錄。不得使用共用網絡磁碟作為即時 SQLite 資料目錄。

使用 UUID、外鍵、唯一約束、交易、WAL、完整性檢查。學生、科目、班級、修讀、批次、Exam、Session、考場、分配、座位、特殊安排、匯入和生成記錄獨立保存。學生資料只在本地 SQLite 和使用者要求的 Excel 中，不寫入一般運行日誌。

「備份」使用 SQLite backup API，含已提交的 WAL 資料；目標存在則拒絕覆蓋。「還原」先檢查 schema 版本、SQLite 完整性及外鍵，再自動保存現有資料庫為 `before_restore_<時間>_<唯一字尾>.sqlite3`，最後還原選取備份。還原不會自動復原已輸出的外部 Excel。需要回到舊資料，選取自動安全備份再還原。

資料庫保存的是本地個人資料，系統不宣稱加密；請使用機構既有的電腦及檔案存取權限。原始六份含學生資料的附件與測試資料庫沒有納入原始碼發布包。

## 開發與驗證

```powershell
$fofPython = Join-Path $env:LOCALAPPDATA 'FOFExamManager\venv\Scripts\python.exe'
& $fofPython -m pip install -r requirements-dev.txt
& $fofPython -m pytest -q
```

將六份附件放在私人資料夾，設定 `FOF_REFERENCE_DIR` 再執行，可一併跑真實附件測試。沒有附件時該項明確 skipped，其餘測試使用合成學生。參見 [TESTING.md](TESTING.md)、[BUILD.md](BUILD.md)、[CHANGELOG.md](CHANGELOG.md)。

專案模組：`app/importers` 辨識 Excel、`app/database` SQLite、`app/models` 資料記錄、`app/services` 業務規則與復原、`app/ui` Qt 介面、`app/templates` 官方版面、`app/exporters` 驗證與安全發布。`main.py` 只啟動應用程式。
